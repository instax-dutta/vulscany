<objective>
Replace all `error: any` with `error: unknown` + type guards in API route catch blocks (10 instances across 7 files).

Purpose: TypeScript best practice requires `unknown` instead of `any` in catch blocks. Using `any` disables type checking on the caught value, potentially leading to runtime errors when accessing properties that don't exist. With `unknown`, the type must be narrowed via guards before accessing `.message` or other properties.

Output:
- 7 API route files updated with `error: unknown` and appropriate type guards
- All 10 catch blocks converted from `error: any` to `error: unknown`
</objective>

<interfaces>
**Type guard patterns to use for all replacements:**

Pattern 1 — console.error only (most common):
```typescript
// BEFORE:
} catch (error: any) {
    console.error('[Prefix] Message:', error.message);
    return [];
}

// AFTER:
} catch (error: unknown) {
    console.error('[Prefix] Message:', error instanceof Error ? error.message : String(error));
    return [];
}
```

Pattern 2 — error.message accessed for return value:
```typescript
// BEFORE:
} catch (error: any) {
    console.error('[API] Error:', error);
    return NextResponse.json(
        { error: 'Message', details: error.message },
        { status: 500 }
    );
}

// AFTER:
} catch (error: unknown) {
    const message = error instanceof Error ? error.message : 'Unknown error';
    console.error('[API] Error:', error);
    return NextResponse.json(
        { error: 'Message', details: message },
        { status: 500 }
    );
}
```

Pattern 3 — error object used in template:
```typescript
// BEFORE:
} catch (error: any) {
    console.error(`[Prefix] Failed to X ${name}:`, error.message);
    return [];
}

// AFTER:
} catch (error: unknown) {
    console.error(`[Prefix] Failed to X ${name}:`, error instanceof Error ? error.message : String(error));
    return [];
}
```

Each replacement must:
1. Change `error: any` to `error: unknown`
2. Guard every `.message` access with `error instanceof Error ? error.message : ...`
3. For `console.error('msg:', error)` — the bare `error` is fine without a guard (console.error accepts unknown)
4. For `throw error` or `throw new Error(...)` — ensure proper handling
</interfaces>
